# Yummy Jeju

JSP/Servlet 기반 제주 맛집 정보 제공 및 커뮤니티 웹 플랫폼입니다.  
사용자는 제주 맛집 정보를 조회하고, 리뷰·게시글·댓글·북마크 등의 기능을 사용할 수 있습니다.  
관리자는 회원, 가게, 신고, 문의, 이벤트 등을 관리할 수 있으며, 신고 처리와 가게 승인 등 운영 기능을 수행할 수 있습니다.

## Troubleshooting

### 1. 네이버 로그인 사용자 처리 및 세션 관리

#### Problem

네이버 로그인 사용자는 일반 회원가입 사용자와 달리 비밀번호나 전화번호 등의 일부 정보가 없기 때문에, 기존 회원 처리 흐름과 동일하게 다루기 어려웠습니다.

#### Cause

네이버 로그인 API에서 전달받는 사용자 정보와 기존 회원 테이블에서 요구하는 회원 정보 항목이 완전히 일치하지 않았습니다.

#### Solution

네이버 로그인 요청에서 전달된 이메일, 닉네임, 프로필 이미지를 JSON으로 받아 처리하고, 이메일을 기준으로 기존 회원 여부를 확인했습니다. 신규 회원인 경우 기본값을 함께 저장하여 회원 데이터를 생성하고, 로그인 성공 후 세션에 사용자 식별값을 저장하도록 구성했습니다.

#### Result

네이버 계정으로도 회원가입 및 로그인 흐름을 통합하여 처리할 수 있도록 개선했습니다.

### 2. 신고 처리와 사용자 제한 흐름

#### Problem

신고가 접수된 뒤 단순히 신고 상태만 변경하면, 문제가 된 게시글·댓글·리뷰 처리와 신고당한 회원의 활동 제한을 함께 관리하기 어려웠습니다.

#### Cause

신고 데이터, 신고 대상 콘텐츠, 신고당한 회원 정보가 각각 분리되어 있어 신고 처리 시 여러 기능이 함께 동작해야 했습니다.

#### Solution

신고 처리 Servlet에서 신고 상세 정보를 조회한 뒤, 신고 유형에 따라 게시글, 댓글, 리뷰를 구분하여 삭제하도록 구성했습니다. 이후 신고당한 회원에게 활동 제한을 적용하는 로직을 연결했습니다.

#### Result

신고 접수 이후 콘텐츠 처리와 회원 제재가 함께 이루어지도록 관리자 기능의 흐름을 정리했습니다.

### 3. 가게 승인 후 목록 상태 유지

#### Problem

관리자가 가게를 승인한 뒤 기존에 보고 있던 목록의 페이지 번호, 검색 조건이 유지되지 않으면 다시 같은 위치로 돌아가기 불편했습니다.

#### Cause

가게 승인 처리 후 단순히 목록 페이지로 이동하면 기존 검색 조건과 페이징 정보가 사라질 수 있었습니다.

#### Solution

가게 승인 처리 후 `pageNum`, `searchType`, `searchKeyword` 값을 함께 전달하여 기존 목록 조건을 유지한 상태로 관리자 페이지에 다시 접근하도록 구성했습니다.

#### Result

관리자가 승인 처리 후에도 기존 검색·페이징 흐름을 유지할 수 있어 관리 편의성을 높였습니다.
